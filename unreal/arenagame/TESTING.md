# PIE testing checklist

## Build and player controls

1. Open `Arenagame.uproject` with Unreal Editor 5.8 and compile the `ArenagameEditor` target.
2. Create a test map with a floor, a Player Start, basic lighting and a GameMode override if needed. Ensure the project GameMode uses `AArenagameCharacter` (the C++ default does).
3. Press Play. Test WASD, mouse look, jump, sprint, crouch, flashlight toggle and the E interaction trace against a test interactable.
4. Sprint until stamina is depleted; confirm sprint is refused and stamina regenerates while not sprinting. Toggle the flashlight and confirm its battery drains while on.
5. Inspect the character's `SurvivalStatus` component in PIE/Blueprint to observe health, stamina, fear, battery, sanity, fear movement multiplier, camera shake intensity and heartbeat volume.

## Interactions and objectives

1. Place an `AObjectiveManager` in the map and a child Blueprint of `APickupActor`. Assign its objective item to Fuel or Keycard.
2. Interact with the pickup. Confirm the manager's objective state changes and the pickup is destroyed.
3. Call `SetPowerRestored(true)` and `SetEscapeReached(true)` from a test Blueprint/button to check objective progression. These are intentionally small API hooks, not a full inventory/quest UI.
4. Place a child of `AInteractableActor` and implement/override `Interact` in Blueprint to verify the interaction interface event.

## Fear / sanity response

1. Add `UFearSanityManagerComponent` to the player (or a character child BP; `AArenagameCharacter` has one by default).
2. In a dim test map, turn the flashlight off; observe fear rising and sanity responding. Turn it on to reduce darkness exposure.
3. Place an `AStalkerEntity` within `EntityDetectionRadius`; observe proximity/visibility influence. Move behind a wall to test line-of-sight behavior.
4. Trigger `ReportScriptedScare` from a Blueprint and check the fear response, then verify movement speed and the exposed shake/heartbeat values respond.

## Stalker navigation

1. Place an `AStalkerEntity`, assign a list of patrol point actors, add an AI Controller (set a suitable controller class in a child BP), then add a Nav Mesh Bounds Volume covering all walkable space and press **P** to visualize navigation.
2. Build paths and run PIE. Confirm patrol movement, then call `ReportNoise` on the entity to make it investigate.
3. Expose the player in a clear corridor to test chase; break line of sight and wait for the return-to-patrol timeout.
4. Check Output Log for navigation/controller setup warnings. Navigation data is generated by the Editor and is not part of this source-only project.

## Atmosphere and audio hooks

1. Place a Directional Light and Exponential Height Fog, assign them to `AStormLightingController`, and adjust storm intensity/time scale in Details.
2. Attach `UFlickeringLightComponent` to a movable/point light and tune intensity, frequency and chance.
3. Create an ambient controller Blueprint, assign Sound Cue assets, and invoke its Play Wind / Heartbeat / Entity Stinger / Radio Static functions. Set the heartbeat volume using the survival component's exposed API.
